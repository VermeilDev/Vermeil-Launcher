# Community Code of Conduct

Vermeil is an open-source project guided by its creator and project lead, built with a commitment to privacy, craft, and transparency.

This Code of Conduct outlines expectations for all community interactions—including GitHub Issues, discussions, and issue trackers—to ensure conversations remain constructive, respectful, and productive.

---

## 1. Project Nature & Participation Scope

- **Open Source, Creator Maintained**: The source code of Vermeil is publicly available under the GNU General Public License v3.0 for auditability, privacy verification, and personal forks.
- **Closed to Code Contributions**: We do not accept unsolicited pull requests, external code contributions, or architecture refactors. Pull requests will be closed without review.
- **Welcome Interactions**: Community participation is welcomed in the form of **reproducible bug reports**, **diagnostics**, and **thoughtful feature discussions** via GitHub Issues.

---

## 2. Expected Standards

When opening issues or participating in discussions:

- **Be Respectful & Civil**: Treat fellow users and the project lead with courtesy. Different viewpoints are welcome when expressed constructively.
- **Be Actionable & Specific**: When reporting a bug, provide concrete reproduction steps, system details (OS, Java version, loader), and relevant log outputs.
- **Respect Boundaries & Time**: This is a free, open-source project maintained on personal time. Entitlement, hostile demands, or abusive pressure will not be tolerated.
- **Focus on the Software**: Discussions must remain focused on the technical aspects of Vermeil, Minecraft interoperability, and privacy architecture.

---

## 3. Unacceptable Behavior

The following behaviors will result in immediate moderation action (issue closure, comment removal, or repository block):

- Harassment, insulting, derogatory, or demeaning language.
- Trolling, personal attacks, or bad-faith arguments.
- Spam, duplicate issue flooding, or demanding priority attention.
- Publishing others' private information (doxxing) or violating personal privacy.
- Disruptive conduct that distracts from productive problem-solving.

---

## 4. Moderation & Enforcement

The creator and project lead reserves the sole right to:

1. Close, lock, or remove issues, comments, or discussions that violate these standards or waste project bandwidth.
2. Temporarily or permanently ban accounts engaging in persistent harassment, abuse, or spam across the `VermeilDev` organization.

---

*Thank you for helping keep Vermeil a clean, respectful, and privacy-first space.*
