# Security Policy

## Supported Versions

Only the latest active release and the `main` development branch receive security updates:

| Version | Supported |
|---|---|
| `0.1.0-alpha.1` (and subsequent alphas) | :white_check_mark: |
| Legacy prototype builds (< 0.1.0) | :x: |

## Reporting a Vulnerability

We take the security and privacy of Vermeil seriously. If you believe you have discovered a security vulnerability in Vermeil, please **do not open a public GitHub issue**.

### How to Report

1. **GitHub Private Vulnerability Reporting (Preferred)**:
   - Navigate to the repository's **Security** tab.
   - Click **Report a vulnerability** to open an encrypted private advisory draft.
2. **Direct Contact**:
   - Alternatively, submit a confidential report to `security@vermeillauncher.app` or message the maintainer privately.

### What to Include

Please provide:
- A clear description of the vulnerability and its potential impact.
- Step-by-step reproduction instructions or a minimal Proof of Concept (PoC).
- Your operating system (Windows or Linux) and launcher version.
- Any relevant logs (ensure all personal tokens or paths are sanitized before sending).

### Response Timeline

- **Initial Acknowledgment**: Within 72 hours.
- **Triage & Assessment**: Prompt review with status updates on fix development.
- **Coordinated Disclosure**: Once a fix is verified and deployed, a public release and security advisory will be published with credit to the reporter.

## Safe Harbor

We consider security research conducted under this policy to be authorized. We will not pursue legal action against individuals who:
- Make a good faith effort to avoid privacy violations, data destruction, or service interruption.
- Give us reasonable time to remediate vulnerabilities before disclosing them publicly.
- Do not exploit vulnerabilities beyond the minimum necessary to demonstrate the risk.
